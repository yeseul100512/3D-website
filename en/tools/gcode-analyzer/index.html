What this tool does

It opens G-code written by a slicer (.gcode, .gco, .g) or a .gcode.3mf from Bambu Studio or OrcaSlicer and lists what the slicer recorded in the file: estimated print time, filament length, volume and weight, layer count and height, nozzle and bed temperatures, and the number of filament changes.

It does not rely on the header alone. Every extrusion (E) move is added up to recompute the filament length and to show where the filament goes: outer walls, inner walls, infill, supports and so on. You get a warning when the header disagrees with the moves or was never filled in.

Add several files or plates at once to get a combined total. Results can be copied, saved as CSV or xlsx, or sent to the cost calculator.

How to use it

  1. Export G-code or a .gcode.3mf from your slicer, then drop it on the area above or click the area to choose it. You can select several files at once.
  2. Each file gets a summary, a table per filament and a table per feature. Anything that needs your attention appears as a warning above the tables.
  3. Use the buttons below to copy the results or save them as CSV or xlsx. “Calculate cost with these numbers” opens the cost calculator with the weight and time filled in.

Limits and caveats

  • Print time is the number the slicer wrote into the file; this tool does not make its own prediction. Real prints differ from it because of filament changes, the printer's acceleration limits and what the firmware does before and during the print (heating, bed levelling, calibration).
  • Weight is shown only when the file states a weight or a density. Files from slicers that record length only, such as Cura, give length and volume; if the filament diameter is missing, 1.75 mm is assumed.
  • The per-feature table needs ;TYPE: or ; FEATURE: comments, which Bambu Studio, OrcaSlicer, PrusaSlicer and Cura write. The purge line in the start G-code is usually not counted in the slicer's header, so the summed length can be slightly higher.
  • PrusaSlicer's binary G-code (.bgcode) cannot be read; export plain G-code instead. For files that use firmware retraction (G10/G11) or volumetric extrusion (M200), the summed length may be off.
  • Plain G-code is read in pieces, so files of tens of megabytes do not freeze the page. A .gcode.3mf has to be unpacked in memory, so a very large one may not open on a phone.

Frequently asked questions

Why does the real print take longer or shorter than the slicer said?

A slicer estimates travel time from an acceleration model that never matches the printer's firmware exactly. Heating, bed levelling, filament changes and purging also take a different amount of time on each machine. This tool does not claim to predict better than the slicer; it shows the slicer's own number.

Why is “Summed from E moves” slightly different from the header?

The header is what the slicer calculated; the sum is what the extrusion commands in the file actually add up to. Purge lines in the start G-code and rounding usually cause a difference of under 1%. If the two differ by more than 5%, the file may have been edited or cut off, and a warning is shown.

Can I get a total for several plates?

Yes. Select the G-code files of all plates together, or drop a .gcode.3mf that contains several plates. Each plate gets its own result, and the total time and filament appear at the bottom.

Is my file uploaded anywhere?

No. The file is read and processed inside this browser only. When you continue to the cost calculator, just the weight and time are passed after the # in the address, which browsers do not send to a server.
